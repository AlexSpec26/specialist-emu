# Решения (ADR)

Формат — см. `AGENTS.md`. Старые решения не переписываются: новое решение ссылается на заменённое.

### ADR-001 — Ядра эмуляторов на чистой Java, без Android (2026-10)
- Status: Accepted
- Context: нужно тестировать ядра без телефона.
- Decision: `app/.../core` и `zx/.../core` не зависят от Android; настольные тесты в `tools/`.
- Why: агенты проверяют процессоры и игры на ПК (тесты 8080/Z80, скриншоты игр).
- Consequences: UI-часть не проверяется автоматически — только компиляцией.
- Related: SPEC, ZX

### ADR-002 — Базовые 2 КБ ПЗУ «Специалиста» (C000–C7FF) байт в байт (2026-10-25)
- Status: Accepted
- Context: замер на 127 играх: ~60 % вызывают подпрограммы C000–C7FF напрямую (C010 очистка,
  C037 вывод, C170/C337 клавиатура), почти все читают шрифт C400–C7FF, некоторые (gr_demo)
  читают байты кода как данные.
- Options: (а) своё ПЗУ целиком; (б) сохранить базу, но поправить адрес старта C00C, чтобы
  сразу запускалась оболочка; (в) база без изменений.
- Decision: (в). Старт как у Монитора-2: «PROGRAM ?» → F1 → ВК.
- Why: (б) проверено — gr_demo начал вести себя иначе, т.к. читает байты C00C.
- Consequences: под оболочку 10 КБ (C800–EFFF). Лента/клавиатура/очистка экрана — бесплатно.
- Revisit if: появится аппаратный вариант без нужды в совместимости.
- Related: ROM-000

### ADR-003 — Совместимые подпрограммы на адресах Монитора-2 (2026-10-25)
- Status: Accepted
- Context: Adventure, Fisher Cat, «Команда 13» вызывают внутренние адреса Монитора-2.
- Decision: таблица C800–C836 как у Монитора-2; подпрограммы печати строки, опроса клавиатуры,
  печати hex, печати символа стоят ровно на CE1D, CE5C, CE9D, CEC8 (их поведение повторено).
- Consequences: участок CDD6–CF3B занят фиксированно; код оболочки обходит его.
- Related: ROM-000

### ADR-004 — Интерфейс оболочки: текст 64×32, одно окно, строка задач (2026-10-25)
- Status: Accepted (выбор владельца)
- Options: Mac-подобная графика с курсором; перекрывающиеся окна; плитка; одно окно.
- Decision: одна программа на весь экран, внизу строка запущенных программ (ТАБ — следующая),
  F1 — список программ, псевдографика, плотная сетка 64×32 (клетка 6×8), строчные буквы.
- Why: без мыши свободный курсор неудобен; перекрытие окон дорого по памяти и скорости;
  картинки-значки не нужны; плотная сетка — выбор владельца.
- Consequences: хвосты строчных «у р д щ» почти касаются следующей строки (принято).

### ADR-005 — Сохранение на ленту только из «Магнитофона» (2026-10-25)
- Status: Accepted (предложение владельца)
- Decision: программы оболочки не умеют писать на ленту; пользователь сохраняет диапазон памяти
  (текст, код) в «Магнитофоне». Экономит место в ПЗУ.

### ADR-006 — Карта памяти ZX как у «Специалиста», 1–4 байта в строке (2026-10-25)
- Status: Accepted (выбор владельца «для начала»)
- Options: (а) прежняя 8 КБ × 32 байта; (б) полоса «Спектрум» с экраном в цвете;
  (в) столбцы по 256 строк, 1–4 байта в строке; вид «байты».
- Decision: (в); вид «байты» удалён. (б) отложен (ZX-IDEA-001).
- Why: ширина строки = ширина графики игры → тайлы (1 байт) и спрайты (2 байта) видны.

### ADR-007 — Вспышки карты ZX во времени эмулятора (2026-10-25)
- Status: Accepted
- Decision: метки обращений — такты эмулятора; длительность вспышки = настройка × скорость,
  но не меньше одной команды; при шагах по одной команде светится только она.
- Related: ZX-011; SPEC так не умеет (SPEC-IDEA-001).

### ADR-008 — История ZX для шагов назад (2026-10-25)
- Status: Accepted
- Decision: снимок состояния на каждый кадр, 10 с (500 кадров), с записью нажатых клавиш;
  шаг назад = восстановить снимок и точно переиграть. Шаг = 1 команда (не такт).
- Why: потактовое ядро Z80 — большая переделка ради малого.
- Consequences: сигнал с микрофона при откате не воспроизводится.

### ADR-009 — Декодер магнитофона подстраивает скорость плавно (2026-10-25)
- Status: Accepted
- Decision: чтение звука с микрофона ускоряется/замедляется до ±2 % вместо скачков.
- Why: часы звуковой карты и эмулятора расходятся; скачки портили длинные загрузки (найдено
  тестом-петлёй на ZX). Применено и в SPEC.

### ADR-010 — Игры в комплекте ZX — только свободно распространяемые (2026-10-25)
- Status: Accepted
- Decision: The Mojon Twins (CC BY-NC-SA 3.0), «Lost in Worlds» (Nihirash, «Feel free to
  redistribute»). ПЗУ 48K — с разрешения Amstrad для эмуляторов. Только 48K-игры.

### ADR-011 — Ключ подписи APK лежит в репозитории (2026-10)
- Status: Accepted, **под вопросом** (противоречит правилу 7 `AGENTS.md`)
- Context: `app/emu.keystore`, пароль в `app/build.gradle` и `zx/build.gradle`.
- Risk: им можно подписать поддельное обновление этих приложений.
- Option: перенести в GitHub Secrets — подпись не изменится. Ждёт решения владельца (OPS-001).

### ADR-012 — Флиппер заморожен (2026-10-25)
- Status: Accepted (решение владельца)
- Decision: автоматическая сборка отключена (только ручной запуск), код не трогать.

### ADR-013 — Изоляция продуктов в одном репозитории (2026-10-25)
- Status: Accepted 2026-10-25 — владелец: «оставляем пока один репозиторий. если станет тесно - скажи»
- Context: владелец хочет, чтобы работа над одной частью не задевала другие; предложил долгие
  ветки по продуктам или новый репозиторий.
- Options:
  1. Долгоживущие ветки `specialist-emu`, `specialist-rom`, `zx`. Минус: ветки расходятся,
     общие исправления (декодер ленты, инструменты) переносить вручную; `main` теряет смысл;
     релизы с веток неудобны с телефона.
  2. Отдельные репозитории на продукт. Плюс: полная изоляция, у каждого свои Releases, Issues и
     память; агент видит только свой продукт. Минус: переезд, общие инструменты копируются.
  3. Один репозиторий, папка на продукт, сборка каждого продукта запускается только от своих
     папок, свои теги релизов, короткие ветки на задачу (`claude/rom-001`).
- Сейчас сделано (3): сборки разведены по путям (`build.yml` — app, `zx.yml` — zx, `rom.yml` —
  shell, флиппер вручную). Вариант 2 можно сделать позже без потери истории (`git subtree split`).

### ADR-014 — Ключ подписи только в GitHub Secrets (2026-10-25)
- Status: Accepted (перенос — решение владельца); вариант ключа — ждёт выбора (OPS-001)
- Supersedes: ADR-011
- Context: репозиторий публичный, ключ `app/emu.keystore` и пароль были видны всем с первого
  коммита. Удаление файла не убирает его из истории; переписывание истории — разрушительно и
  бесполезно для уже скачанных копий.
- Options: (A) перенести старый ключ в секреты — без переустановки, но ключ уже публичен;
  (B) новый ключ только в секретах — настоящая защита, но приложения один раз переустановить
  (Android при удалении стирает Android/data/… — сохранения нужно заранее скопировать).
- Decision so far: сборка читает ключ из секретов `SIGNING_KEYSTORE_B64`, `SIGNING_STORE_PASSWORD`,
  `SIGNING_KEY_ALIAS`, `SIGNING_KEY_PASSWORD`; пока их нет — старый ключ из репозитория.
- Access: агенты (Claude, ChatGPT/Codex, Grok) ключ не видят и не используют. Подписывает только
  GitHub Actions; значения секретов не может прочитать никто, включая владельца. Агенты для
  своих проверок собирают без ключа (`assembleDebug` / проверка компиляцией) и такие файлы
  владельцу не дают. Менять секреты может только владелец в веб-интерфейсе GitHub.
- Consequences: потеря файла ключа (вариант B) = следующая версия ставится только после удаления
  старой. Владельцу хранить файл ключа и пароль у себя (менеджер паролей/облако).
