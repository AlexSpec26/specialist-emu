# Решения (ADR)

Формат — см. `AGENTS.md`. Старые решения не переписываются: новое решение ссылается на заменённое.

### ADR-001 — Ядра эмуляторов на чистой Java, без Android (2026-10)
- Status: Accepted
- Context: нужно тестировать ядра без телефона.
- Decision: `app/.../core` и `zx/.../core` не зависят от Android; настольные тесты в `tools/`.
- Why: агенты проверяют процессоры и игры на ПК (тесты 8080/Z80, скриншоты игр).
- Consequences: UI-часть не проверяется автоматически — только компиляцией.
- Related: SPEC, ZX

### ADR-002 — Базовые 2 КБ ПЗУ «Специалиста» (C000–C7FF) байт в байт (2026-10-25)
- Status: Accepted
- Context: замер на 127 играх: ~60 % вызывают подпрограммы C000–C7FF напрямую (C010 очистка,
  C037 вывод, C170/C337 клавиатура), почти все читают шрифт C400–C7FF, некоторые (gr_demo)
  читают байты кода как данные.
- Options: (а) своё ПЗУ целиком; (б) сохранить базу, но поправить адрес старта C00C, чтобы
  сразу запускалась оболочка; (в) база без изменений.
- Decision: (в). Старт как у Монитора-2: «PROGRAM ?» → F1 → ВК.
- Why: (б) проверено — gr_demo начал вести себя иначе, т.к. читает байты C00C.
- Consequences: под оболочку 10 КБ (C800–EFFF). Лента/клавиатура/очистка экрана — бесплатно.
- Revisit if: появится аппаратный вариант без нужды в совместимости.
- Related: ROM-000

### ADR-003 — Совместимые подпрограммы на адресах Монитора-2 (2026-10-25)
- Status: Accepted
- Context: Adventure, Fisher Cat, «Команда 13» вызывают внутренние адреса Монитора-2.
- Decision: таблица C800–C836 как у Монитора-2; подпрограммы печати строки, опроса клавиатуры,
  печати hex, печати символа стоят ровно на CE1D, CE5C, CE9D, CEC8 (их поведение повторено).
- Consequences: участок CDD6–CF3B занят фиксированно; код оболочки обходит его.
- Related: ROM-000

### ADR-004 — Интерфейс оболочки: текст 64×32, одно окно, строка задач (2026-10-25)
- Status: Accepted (выбор владельца)
- Options: Mac-подобная графика с курсором; перекрывающиеся окна; плитка; одно окно.
- Decision: одна программа на весь экран, внизу строка запущенных программ (ТАБ — следующая),
  F1 — список программ, псевдографика, плотная сетка 64×32 (клетка 6×8), строчные буквы.
- Why: без мыши свободный курсор неудобен; перекрытие окон дорого по памяти и скорости;
  картинки-значки не нужны; плотная сетка — выбор владельца.
- Consequences: хвосты строчных «у р д щ» почти касаются следующей строки (принято).

### ADR-005 — Сохранение на ленту только из «Магнитофона» (2026-10-25)
- Status: Accepted (предложение владельца)
- Decision: программы оболочки не умеют писать на ленту; пользователь сохраняет диапазон памяти
  (текст, код) в «Магнитофоне». Экономит место в ПЗУ.

### ADR-006 — Карта памяти ZX как у «Специалиста», 1–4 байта в строке (2026-10-25)
- Status: Accepted (выбор владельца «для начала»)
- Options: (а) прежняя 8 КБ × 32 байта; (б) полоса «Спектрум» с экраном в цвете;
  (в) столбцы по 256 строк, 1–4 байта в строке; вид «байты».
- Decision: (в); вид «байты» удалён. (б) отложен (ZX-IDEA-001).
- Why: ширина строки = ширина графики игры → тайлы (1 байт) и спрайты (2 байта) видны.

### ADR-007 — Вспышки карты ZX во времени эмулятора (2026-10-25)
- Status: Accepted
- Decision: метки обращений — такты эмулятора; длительность вспышки = настройка × скорость,
  но не меньше одной команды; при шагах по одной команде светится только она.
- Related: ZX-011; SPEC так не умеет (SPEC-IDEA-001).

### ADR-008 — История ZX для шагов назад (2026-10-25)
- Status: Accepted
- Decision: снимок состояния на каждый кадр, 10 с (500 кадров), с записью нажатых клавиш;
  шаг назад = восстановить снимок и точно переиграть. Шаг = 1 команда (не такт).
- Why: потактовое ядро Z80 — большая переделка ради малого.
- Consequences: сигнал с микрофона при откате не воспроизводится.

### ADR-009 — Декодер магнитофона подстраивает скорость плавно (2026-10-25)
- Status: Accepted
- Decision: чтение звука с микрофона ускоряется/замедляется до ±2 % вместо скачков.
- Why: часы звуковой карты и эмулятора расходятся; скачки портили длинные загрузки (найдено
  тестом-петлёй на ZX). Применено и в SPEC.

### ADR-010 — Игры в комплекте ZX — только свободно распространяемые (2026-10-25)
- Status: Accepted
- Decision: The Mojon Twins (CC BY-NC-SA 3.0), «Lost in Worlds» (Nihirash, «Feel free to
  redistribute»). ПЗУ 48K — с разрешения Amstrad для эмуляторов. Только 48K-игры.

### ADR-011 — Ключ подписи APK лежит в репозитории (2026-10)
- Status: Accepted, **под вопросом** (противоречит правилу 7 `AGENTS.md`)
- Context: `app/emu.keystore`, пароль в `app/build.gradle` и `zx/build.gradle`.
- Risk: им можно подписать поддельное обновление этих приложений.
- Option: перенести в GitHub Secrets — подпись не изменится. Ждёт решения владельца (OPS-001).

### ADR-012 — Флиппер заморожен (2026-10-25)
- Status: Accepted (решение владельца)
- Decision: автоматическая сборка отключена (только ручной запуск), код не трогать.

### ADR-013 — Изоляция продуктов в одном репозитории (2026-10-25)
- Status: Accepted 2026-10-25 — владелец: «оставляем пока один репозиторий. если станет тесно - скажи»
- Context: владелец хочет, чтобы работа над одной частью не задевала другие; предложил долгие
  ветки по продуктам или новый репозиторий.
- Options:
  1. Долгоживущие ветки `specialist-emu`, `specialist-rom`, `zx`. Минус: ветки расходятся,
     общие исправления (декодер ленты, инструменты) переносить вручную; `main` теряет смысл;
     релизы с веток неудобны с телефона.
  2. Отдельные репозитории на продукт. Плюс: полная изоляция, у каждого свои Releases, Issues и
     память; агент видит только свой продукт. Минус: переезд, общие инструменты копируются.
  3. Один репозиторий, папка на продукт, сборка каждого продукта запускается только от своих
     папок, свои теги релизов, короткие ветки на задачу (`claude/rom-001`).
- Сейчас сделано (3): сборки разведены по путям (`build.yml` — app, `zx.yml` — zx, `rom.yml` —
  shell, флиппер вручную). Вариант 2 можно сделать позже без потери истории (`git subtree split`).

### ADR-014 — Ключ подписи только в GitHub Secrets (2026-10-25)
- Status: Accepted, выполнено 2026-10-25 — владелец выбрал (B): новый ключ RSA 4096, псевдоним `emu`,
  SHA-256 63:FA:C0:1B:…:9C:65; файл ключа и пароль хранит владелец
- Supersedes: ADR-011
- Context: репозиторий публичный, ключ `app/emu.keystore` и пароль были видны всем с первого
  коммита. Удаление файла не убирает его из истории; переписывание истории — разрушительно и
  бесполезно для уже скачанных копий.
- Options: (A) перенести старый ключ в секреты — без переустановки, но ключ уже публичен;
  (B) новый ключ только в секретах — настоящая защита, но приложения один раз переустановить
  (Android при удалении стирает Android/data/… — сохранения нужно заранее скопировать).
- Decision: сборка читает ключ только из секретов `SIGNING_KEYSTORE_B64`, `SIGNING_STORE_PASSWORD`,
  `SIGNING_KEY_ALIAS`, `SIGNING_KEY_PASSWORD`; без них или с неверными значениями — падает.
  `app/emu.keystore` и пароли удалены из репозитория (старый ключ остался в истории — он больше
  ничего не подписывает).
- Access: агенты (Claude, ChatGPT/Codex, Grok) ключ не видят и не используют. Подписывает только
  GitHub Actions; значения секретов не может прочитать никто, включая владельца. Агенты для
  своих проверок собирают без ключа (`assembleDebug` / проверка компиляцией) и такие файлы
  владельцу не дают. Менять секреты может только владелец в веб-интерфейсе GitHub.
- Consequences: потеря файла ключа (вариант B) = следующая версия ставится только после удаления
  старой. Владельцу хранить файл ключа и пароль у себя (менеджер паролей/облако).

### ADR-015 — Быстрый текст оболочки группами по 4 символа (2026-10-25)
- Status: Accepted (ROM-001)
- Context: клетка 6 точек, байт 8 — каждый символ раньше читал и переписывал байты экрана
  (~1400 тактов на символ).
- Options: (а) группы по 4 символа = 3 целых байта; (б) сдвинутые копии шрифта (+2…4 КБ);
  (в) теневой текстовый буфер (2–4 КБ ОЗУ, конфликтует с памятью пользователя).
- Decision: (а). Глифы 80–FF перенесены в EC00–EFFF (по странице: адрес глифа без сложений);
  свободное место до CE1D заполнено байтами Монитора-2 (Piton 3 читает CD21–CD28 как данные).
- Consequences: ~750 тактов на символ в строке; одиночный PUTCH по-прежнему медленный.
- Revisit if: не хватит скорости в «Памяти»/«Отладке» и останется 2+ КБ ПЗУ.

### ADR-016 — Без ассемблера и дизассемблера в ПЗУ (2026-10-25)
- Status: Accepted (решение владельца, ROM-Q3)
- Context: после «Памяти» свободно ~2,2 КБ, планов ~4,4 КБ.
- Decision: «отрезаем ассемблер и дизассемблер». «Отладка» показывает код байтами по командам
  (длины команд считаются правилами, без таблиц мнемоник).
- Consequences: читать код — по hex; ROM-004 отклонён.

### ADR-017 — Код в пустотах ПЗУ (2026-10-25)
- Status: Accepted (ужатие по просьбе владельца)
- Decision: байты Монитора-2 сохраняются только на CD21–CD28 (их читает Piton 3; проверено на
  127 играх ShellCompat); остальное место до CE1D и коды BD–DF таблицы символов (EDE8–EEFF,
  у них нет глифов) заняты кодом. Таблица символов разделена: glyphs.inc (80–BC) и
  glyphs_hi.inc (E0–FF), их делает mkfont.py.
- Consequences: игра, читающая другие байты Монитора-2 как данные, может вести себя иначе;
  тестовые 127 игр — как раньше. Коды BD–DF печатать нельзя (выйдет мусор).

### ADR-018 — «Отладка» вместо «Монитора» (2026-10-25)
- Status: Accepted (решение владельца: «выкинуть монитор и вернуть отладчик, плюс имена в
  магнитофоне, и заполнение в памяти»)
- Consequences: программы — Обзор, Память, Магнитофон, Отладка. Команды Монитора-2 C, K, N, H
  недоступны; monitor.asm лежит отдельно. Переменные «Магнитофона» перенесены в 8E50 (TVARS),
  стек оболочки — от 8F00 вниз до ~8E6E.

### ADR-019 — Вторая прошивка «среда разработки» из тех же исходников (2026-10-25)
- Status: Accepted (решение владельца)
- Decision: `shell/src/devel.asm` — вторая верхняя сборка рядом с `main.asm`; общие части
  (common.asm, compat1–4.asm, kernel.asm, scroll.asm, hexin.asm) одни на обе; пустоты ПЗУ
  каждая прошивка заполняет своим. CI выпускает обе в одном релизе rom-build-N.
- Ассемблер — перебор 256 кодов через тот же разбор, что у дизассемблера: принимает ровно то,
  что дизассемблер печатает; без меток и директив (обсуждено с владельцем).

### ADR-020-ATARI — CPU-first продолжение каркаса Atari (2026-10-26)
- Status: Superseded by ADR-022 (было: Accepted, реализация первого этапа roadmap atari/README)
- Context: владелец попросил продолжить ветку Atari, содержащую лишь инспектор памяти.
- Decision: сначала тестируемое чистое Java ядро документированного NMOS 6502, PIA banking
  и загрузка своих ROM; следующими идут ANTIC/GTIA/POKEY и игровые форматы.
- Why: Klaus conformance test даёт независимое доказательство работы CPU до видеочипов.
- Consequences: instruction timing без DMA/RDY; undocumented opcodes явно останавливают
  исполнение; ни игры, ни полный Atari boot пока не заявляются. ROM не распространяются.
- Build: отдельный workflow и atari-build-N prerelease; общий ключ только в GitHub Actions.
- Related backlog IDs: ATARI-001. Суффикс ATARI исключает коллизию с ADR-020 в SPEC PR #2.

### ADR-021-ATARI — Игровой runtime на Atari800 (2026-10-26)
- Status: Accepted (реализация поручения ATARI-002, review PR #3)
- Context: владелец просит продолжать до полноценного игрового APK, не только CPU inspector.
- Options: самостоятельно реализовать ANTIC/GTIA/POKEY/SIO; интегрировать существующее ядро.
- Decision: Atari800 7.0.0/libretro GPL-2.0-or-later по pinned revision; исходники в Atari-модуле,
  corresponding source прилагается к каждому APK, лицензии сохранены в источниках и приложении.
  Java M6502 остаётся отдельным учебным инспектором, не игровым engine.
- Why: проверенное ядро даёт настоящие видео/звук/игровые форматы; native/JNI тесты подтверждают
  actual boot, input, sound, game media и save-state вместо заявления о готовности по сборке.
- Consequences: NDK и 64-bit ABI, лицензия GPL только Atari-модуля; другие продукты не меняются.
  Встроены только свободные Altirra replacements и оригинальная CC0 demo, не original Atari ROM.
- Related: ATARI-002; дополняет ADR-020-ATARI, не отменяет проверенное Java ядро.

### ADR-022 — Atari: одна машина, учебный Java-инспектор убран (2026-10-26)
- Status: Accepted (решение владельца: «Убрать»)
- Supersedes: ADR-020-ATARI
- Context: после ADR-021-ATARI в APK было две несвязанные машины: игровое ядро Atari800 и
  учебный инспектор на своём Java-6502. Инспектор не видел игровую машину, требовал свои ПЗУ
  и не запускал игр — владелец: «что-то кодекс накрутил там».
- Options: (а) оставить; (б) убрать, а инструменты изучения (карта памяти, шаги) делать на
  настоящем ядре, как в ZX.
- Decision: (б). Удалены InspectorActivity, core/M6502, Atari65XE, CpuBus, AtariCoreTest и тест
  Klaus из CI. Код остаётся в истории git (коммит befcff0 и ранее), к нему можно вернуться.
  ПЗУ, загруженные в инспектор (os.rom/basic.rom), один раз переносятся в игровую машину.
- Consequences: в APK нет пошагового 6502 до задач ATARI-004/005; одно ядро, один набор тестов.
- Revisit if: понадобится учебная модель 6502 отдельно от игр.
- Related: ATARI-001, ATARI-003

### ADR-023 — Atari: время внутри кадра повтором кадра; приложение на экранах ZX (2026-10-26)
- Status: Accepted (реализация просьбы владельца ATARI-007: «можешь гомогенизировать?»)
- Context: инструменты ZX/SPEC (карта памяти, скорость до 1 такта/с, шаги ±1 команда/±1 с)
  требуют останавливаться между любыми командами. Ядро Atari800 выполняет только целые кадры,
  а его состояние посреди кадра (ANTIC в середине строки) сохранить нельзя.
- Options: (а) переписать цикл ANTIC_Frame так, чтобы его можно было прерывать и продолжать —
  большая правка чужого ядра; (б) своё ядро Atari на Java, как в ZX — месяцы работы;
  (в) хук перед каждой командой: дойдя до нужной точки, выйти из ядра через longjmp и
  никогда не продолжать такую машину — для следующей точки восстановить снимок начала кадра
  и прогнать кадр заново.
- Decision: (в). Снимок начала текущего кадра делается всегда (≈0,01 мс), кольцо снимков —
  каждые 10 кадров за 10 с, органы управления каждого кадра записываются. Назад = снимок +
  повтор; после шага назад вперёд повторяется записанное, пока игра не продолжена
  (engine_forget_future). Время — такты машины (114 на строку, 312 строк). Клавиши подаются
  машине кодами Atari напрямую, минуя раскладку ПК в libretro. Правки vendor: хук и
  трассировка в cpu.c, состояние ввода между кадрами в input.c (иначе повтор не точный).
  Экраны приложения — порт EmuActivity/MainView/MapPanel/EmuThread из ZX, машина спрятана
  за AtariMachine с интерфейсом как у Spectrum48.
- Why: точность проверяется тестом (кадры кусками со 1000+ остановок = целые кадры, побайтно,
  для джойстика и клавиатуры); стоимость остановки — максимум один повтор кадра (~0,5 мс на ПК).
- Consequences: память ~14 МБ на историю; звук в медленном режиме — по целым кадрам; если
  в ядре найдётся ещё состояние вне снимков, повтор разойдётся (тест это ловит).
  Отдельной учебной машины по-прежнему нет (ADR-022).
- Revisit if: найдутся игры, где повтор кадра даёт расхождение.
- Related: ATARI-007 (ATARI-004…006)
