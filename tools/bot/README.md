# Бот-исследователь для «Специалиста» (SPEC-022, прототип на ПК)

Без экрана, на ядре `app/.../core`. Игры и ПЗУ в репозиторий не кладутся — путь к ним передаётся аргументом.

    javac -d /tmp/bot app/src/main/java/com/alexspec/specialist/core/*.java tools/bot/*.java
    # состояние «уровень нарисован, ждёт клавишу» (Lode Runner А. Щербины, 1990: 2 = курсор, 0 = старт)
    java -cp /tmp/bot Snap spec_m2.rom loderun.rks "f 200,k SP 5,f 150,k 2 5,f 50,k 0 5,f 300,k SP 3,f 300,k SP 3,f 300,k SP 3,f 100" ld1.st
    java -cp /tmp/bot Bot spec_m2.rom ld1.st out 90      # 90 с игры, кадры с нарисованным поиском в out/

Профиль игры — `prof/<игра>.txt`: стартовый сценарий для `Snap`, где герой (`xy` — свои
координаты, `addr` — адрес героя на экране: строка и 90h+колонка), жизни и очки (`byte`/`ascii`
в памяти или `rect` — прямоугольник экрана, любое изменение которого = событие), клавиши огня,
шаг (кадров на одно действие), `dead=tick <адрес>` — игра замирает в миг гибели, `tail` — сколько
кадров игра «показывает смерть», прежде чем снять жизнь.

    java -cp /tmp/bot Bot spec_m2.rom ld1.st out 60 tools/bot/prof/loderun.txt

Как ищет: каждые 2 шага — 64 варианта на 12 шагов вперёд на копиях машины (половина — правки
прошлого лучшего плана, половина — случайные). Оценка: новая клетка 8×8 — +6, уже виденная —
+1/√(посещений), «скука» — +0,6 за каждые 8 точек, на которые конец плана ушёл от того места, где
герой крутился последние ~8 с; очки — +4 за событие (или за каждые 25 очков); потеря жизни —
−1 000 000. Затем варианты по порядку проверяются «доживанием» ещё `tail` кадров (стоять, идти
дальше, два случайных бегства); идёт первый, кто выжил, верная смерть — только если не выжил никто.

Найти, где в памяти герой: `KeyScan` (что меняет каждая клавиша), `Auto` (байты, идущие за ←/→ и
↑/↓), `Rand` + разбор дампа (жизни, очки), `Top` (строка состояния на экране).
